# 🐭 ドロボーマウス 🐱

2チーム対戦（2人 vs 2人）の攻守交代制ゲーム。舞台は猫が運営するスーパー。
ネズミ側はNPCネズミに紛れて商品を盗んで出口から持ち出すと、商品の値段分のスコアを獲得。
猫側は監視カメラ越しに怪しいネズミを見つけて「ダウト」（クリック）で暴く。

- Three.js（3D描画）+ Firebase Realtime Database（同期）+ Vite + TypeScript
- ボイスチャットはZoom等の外部サービスで代用（チームごとに別ルームを作る）

## ルール

- **1ラウンド1分 × 2ラウンド**。前半はチームAがネズミ（攻撃）・チームBが猫（守備）、後半で攻守交代。ラウンドは**時間切れ**、または**猫がネズミ（プレイヤー）全員のダウトに成功**した時点で即終了する（後半なら試合終了）
- **ネズミ**: 好きな商品棚の近くで**「盗む」ボタン**を押し、そのまま5秒とどまると盗み成功（棚から離れると中断）。その間**体が左右にわずかに揺れて目立つ**。盗んだ商品を出口（緑ゲート）から持ち出すと**商品の値段分のスコアを獲得**（商品ごとに値段が違い、複数持ち出せば合計金額が入る）。**店の外に出たらそのラウンドには戻れない**（チキンレース方式）。欲張って盗み続けるか早めに持ち出すかの駆け引き
- **猫**: 2人とも監視カメラ役。店内カメラ12台を**オンライン⇔オフラインでトグル**（同時オンラインは1人3台まで。画面上寄りに3枚のモニタ、一番下にカメラマップ。モニタにカーソルを乗せるとそのモニタが拡大し、他の2枚は縮小）。カメラ映像の怪しいネズミをクリックすると「ダウト」
  - プレイヤーのネズミを当てたら、そのネズミは**所持中の商品を没収され、退場**する（ラウンドは続く。泥棒全員が退場したらラウンド即終了）
  - NPCだったら空振り。ダウトは**1ラウンドにつき各プレイヤー2回まで**
- **監視の可視化**: オンラインのカメラは**ポール上部の球体が赤く発光**し、**視野に入っている床が明るくなる**。ネズミは「みられている場所」と死角を見分けながら動く
- **猫同士の連携**: カメラマップには自分がオンにしたカメラの視野が**赤**、相方がオンにしたカメラの視野が**青**で描かれ、2人でどこを見張っているかが分かる
- **着せ替えと名前**: ネズミのカプセルの色は着せ替えで12色のパレットから選ぶ。NPCも同じパレットからランダムに配色されるので、色ではプレイヤーとNPCを見分けられない。ネズミ側のクライアントでは仲間のカプセルの頭上に**名前**が出る（監視カメラ・観戦には映らない）。ネズミの視点はデフォルトで一人称、ボタンで追従カメラに切替
- **セット制**: 1セット = 前半＋後半（攻守交代1回）。ルーム作成時にホストが**セット数（1/2/3/5）とセットごとのステージ**を決める。各セットの終了時にそのセットのリザルト（スコア・獲得セット数）を出し、最終セット後に**最終成績**（セット数 X - Y、各セットのスコア一覧、勝者）を出す。勝敗は獲得セット数、同数なら合計金額、それも同じなら引き分け
- **試合の流れ**: タイトル → 名前入力 → ルーム一覧（アクティブなルームに参加 or 右下のボタンから新規作成）→ ルーム（先攻／後攻の空きカプセルをクリックして陣営に入る。先着順・各2人）→ ホストが開始 → **着せ替え・作戦会議（60秒）**: 前半ネズミの陣営は着せ替え画面、前半猫の陣営は無人の店内でカメラ操作の練習（本番と同じCCTV画面）→ **ステージ紹介**（スイープするカメラ3カット）→ 3・2・1 → 前半 → 攻守交代時にもう一度着せ替え／練習の60秒 → 3・2・1 → 後半 → セットのリザルト → 次のセットの準備 … → 最終成績
- **勝敗**: 2ラウンドで盗んだ商品の累計金額が多いチームの勝ち（同額は引き分け）
- **ステージ**: ロビーでホスト（ゲームマスター）が3種類から選ぶ。選択は部屋の全員に共有され、開始時に確定する
  - **スタンダード**: 従来の広い売り場・カメラ12台
  - **シンプル**: 小さな売り場・カメラ6台・NPC少なめ
  - **2フロア**: 奥半分が2階建て。東側のスロープで2Fへ上がれる（NPCも行き来する）。出口は1Fのみ。カメラは1Fに8台・2Fに4台。カメラマップ／ミニマップは1F・2Fが横に並び、退場後の観戦（俯瞰）はFキーで表示フロアを切り替える

| 役割 | 操作 |
| --- | --- |
| 🐭 ネズミ | WASD / 矢印キーで移動、画面下部の「盗む」ボタンで盗み開始。左下のミニマップ（猫側と同じ図）に自分の位置が出る |
| 🎥 猫（カメラ監視） | 画面下のカメラマップの番号クリック or 数字キーでカメラのオン/オフ切替（3台まで）、中央の映像内のキャラをクリックでダウト、Mでカメラマップの表示切替 |

- 盗む棚の指定（お題）はない。ネズミはいつでも好きな棚を狙える。「盗む」ボタンはネズミにしか表示されない
- ゲームバランスは `src/config.ts` の数値で調整できる

## セットアップ

```bash
npm install
npm run dev
```

### ローカルモード（Firebase不要・すぐ試せる）

`.env` が無い場合は自動でローカルモードになり、**同一PCのブラウザタブ間**で同期する。
`npm run dev` して同じURLをタブで4つ開き、同じ部屋コードで入れば1人で動作確認できる。

### オンラインモード（Firebase）

1. [Firebaseコンソール](https://console.firebase.google.com/)でプロジェクト作成
2. Realtime Database を作成（テストモードでOK。ロケーションは asia-southeast1 など）
3. プロジェクトの設定 > マイアプリ > ウェブアプリを追加して設定値を取得
4. `.env.example` を `.env` にコピーして値を記入
5. `npm run dev` → 各プレイヤーが同じ部屋コードで参加

プロトタイプ用のDBルール（全公開なので遊び終わったら閉じること）:

```json
{
  "rules": {
    "rooms": { ".read": true, ".write": true }
  }
}
```

## 構成

```
src/
├── main.ts          エントリポイント（ロビー⇔着せ替え/練習⇔ゲームの画面遷移、着せ替え時間終了後のラウンド開始）
├── config.ts        ゲームバランス定数（盗み時間・ラウンド時間・ダウト回数など）
├── types.ts         チーム・役割・イベント等の型定義
├── net/
│   ├── adapter.ts   同期インターフェース
│   ├── firebase.ts  Firebase Realtime Database実装
│   └── local.ts     BroadcastChannel実装（同一PCタブ間・開発用）
├── game/
│   ├── game.ts      ゲーム本体（ループ・盗み/ダウト判定・ラウンド進行・勝敗）
│   ├── stages.ts    ステージ定義（フロア・棚・カメラ・スロープ・スポーン位置。3種類）
│   ├── world.ts     店内の3D構築（棚・壁・出口・防犯カメラ・盗みスポット・スロープ・フロア移動）
│   ├── npc.ts       NPCネズミ（seedから決定論的に動くので通信同期が不要）
│   ├── cctv.ts      防犯カメラビュー（中央に同時3台のモニタ・ホバー拡大・接続切替）
│   └── controls.ts  キーボード入力
└── ui/
    ├── lobby.ts     ロビー（タイトル・名前・ルーム一覧/新規作成モーダル・陣営選択・着せ替え画面）
    ├── costume.ts   着せ替えプレビュー（自分と仲間のカプセルを並べて色をライブ反映）
    ├── titlebg.ts   タイトル背景（カプセルがうろつく3D）
    ├── map.ts       カメラマップ（猫: Mでモーダル / ネズミ: 左下ミニマップに自己位置を重ねる）
    └── hud.ts       ゲーム中HUD（タイマー・スコア・盗むボタン・通知）
```

## 実装メモ

- **NPCの同期**: NPCはゲームseedから決定論的に動く（`NpcSim.posAt(t)`）。全クライアントが同じ計算をするため位置の通信が不要。seedはラウンドごとに変わる
- **部屋の後始末**: プレイヤー情報は切断時に自動削除されるが、`phase`・`events` は結果画面の「ロビーに戻る」でしか消えない。そのため、入室時に自分以外の誰もいない部屋は残骸とみなして `phase` をロビーに戻し、`events`/`pos`/`cams` を削除する。保険として、startAt が1ラウンド分より十分古い `playing` はロビー扱いにする（`isStalePhase`）
- **スコア**: `escape` イベント（持ち出した商品の合計金額 `value` を含む）の積み上げから全クライアントが同じ集計をする。イベントは試合を通して保持し、ロビーに戻るときに消す
- **ラウンド進行**: 時間切れ、またはネズミプレイヤー全員が `caught` になった時点（ダウト演出後）。ホスト（不在時は2秒後に誰でも）が `phase` を書き込む楽観的な方式（プロトタイプ想定）
- **フェーズ**: `lobby` → `costume`（`until` まで。ホストの開始と前半終了時に入る）→ `playing`（`startAt`。前半は startAt の前に `introSec`＋`countdownSec`、後半は `countdownSec` の猶予）→ `setEnd`（次のセットがあるとき。`until` まで表示）→ `costume`（次のセット）… → `ended`。`costume`/`setEnd` の終了は main.ts の setInterval がホスト（不在時は2秒後に誰でも）として次のフェーズを書く。セット構成（`set`/`sets`/`stages`/`results`）は phase に持ち回る
- **セットごとの集計**: イベントに `set` を含め、Game は自分のセットのイベントだけを集計する（イベントは試合を通して残す）。試合構成は `rooms/{room}/match`（`{ sets, stages }`）にルーム作成時に書く
- **練習モード**: `costume` フェーズ中、次のラウンドで猫になる陣営は `Game` を `practice=true` で作る（NPC・プレイヤー無し、位置/イベント送受信無し、タイマーは `until` の残り）。フェーズが `playing` になると作り直す
- **アクティブなルーム一覧**: `roomIndex/r_{code}/{pid}` = 名前 を入室時に書き、切断時に自動削除。メンバーが1人以上いるルームだけ一覧に出す（`rooms` 全体を購読すると位置情報まで流れるため別ノードにしている）
- **名前ラベルの秘匿**: 名前スプライトは Three.js のレイヤ2に置き、泥棒陣営のクライアントの追従/一人称カメラだけがそのレイヤを描画する。CCTVカメラ・観戦の俯瞰では描画しない
- **Firebase の注意**: `set()` に `undefined` を含むオブジェクトを渡すと書き込みが拒否される。省略可能なフィールドは入れないこと
- **ダウト成功**: `caught` イベントを受けた当人が演出時間だけその場で固まった後、姿を消して退場し、俯瞰で観戦になる（所持商品は没収）。ダウトは成功でも回数を消費する
- **脱出（チキンレース）**: 商品を持って出口ゾーンに入ると `escape` イベントで所持金額分をスコアに加算し、当人はダウト時と同じ退場処理（観戦）になる。リスポーンはしない。泥棒全員が退場（ダウト or 脱出）したらラウンド即終了
- **ダウト判定**: CCTVのクリック位置から該当カメラのNDC座標を求めてレイキャスト。プレイヤーのネズミに当たれば `caught`、NPCなら `miss`
- **監視状態の同期**: 各猫のオンラインカメラIDを `rooms/{room}/cams/{pid}` に書き、全クライアントが購読して球の発光と床ハイライトに反映する
- **視野と死角**: カメラの実効視野はマップ表示・床ハイライト・死角リスポーン探索で同じ2Dレイキャスト（`castRay`）を使って一貫させている。死角リスポーンは1Fの全カメラから見えない歩行可能地点を起動時に自動探索する
- **ステージ選択**: ホストの選択を `rooms/{room}/stage` に書き、ロビーの全員が購読して表示する。開始時に `phase.stage` へコピーし、後半戦の `phase` にも引き継ぐ
- **複数フロア**: 各フロアは独立した2Dレイアウト（`FloorDef`）で、スロープ（`RampDef`）の矩形内では両端のフロアの高さを線形補間する。プレイヤーはスロープの端（下のフロアからは下端、上のフロアからは上端）からしか出入りできず、横は手すりで塞ぐ。歩行グリッド（`NavGrid`）はフロアごとのレイヤをスロープ上端のリンクで繋いでおり、NPCも坂を通って行き来する。上階の静的メッシュは Three.js のレイヤ1に置き、1Fにいるネズミの追従カメラでは非表示にして床板で視界が塞がれないようにしている（CCTV・一人称は全レイヤ描画）。位置同期には `f`（フロア番号）を含める。2Dの視野（マップ・床ハイライト）はフロアの範囲内で打ち切り、吹き抜け越しの見下ろしは扱わない
