# 🐭 まんびきチュー ~SUPER TINY WAR~

2チーム対戦（2 vs 2）の攻守交代制ゲーム。舞台はネズミたちが暮らす「タイニータウン」のスーパー。
**まんびきサイド**は一般客（NPC）に紛れて商品を盗み、出口から持ち出すと商品のポイントを獲得。
**監視サイド**は監視カメラ越しに怪しいネズミを見つけて「ダウト」（クリック）で暴く。

- Three.js（3D描画）+ Firebase Realtime Database（同期）+ Vite + TypeScript
- ボイスチャットはZoom等の外部サービスで代用（チームごとに別ルームを作る）
- 画面の文言・遷移は `docs/まんびきチュー_共同制作資料.pdf` の「フロー」章に合わせている（用語の対応は下記）

## 用語

| 画面上の呼び方 | 意味 | コード上の名前 |
| --- | --- | --- |
| TEAM PINK / TEAM BLUE | 2つのチーム（色は固定） | `Team` の `'A'` / `'B'` |
| まんびきサイド / 監視サイド | そのターンの攻撃側 / 守備側 | `amMouse` / `amCat` |
| ターン（第1ターン・第2ターン） | 1分の攻守どちらか。第2ターンで攻守交代 | `round` (1 / 2) |
| ラウンド（1st ROUND …） | 第1ターン＋第2ターン | `set` |
| pt | 商品のポイント（= 得点） | `price` |
| エリアの住所 | 部屋コード（XX-XX-XX） | `room` |

## ルール

- **1ターン1分。第1ターンと第2ターンで攻守を交代**し、それを1ラウンドとする。ラウンド数はエリア作成時にホストが決める（1/2/3/5）。ターンは**時間切れ**、または**まんびきサイド全員の退場**（ダウト or 脱出）で即終了
- **先攻**（第1ターンにまんびきするチーム）はロビーでホストが「PINK / BLUE / ランダム」から選ぶ。ランダムは START 時に決まる
- **まんびきサイド**: 一般客に変装して店内へ（カプセルの色は**ランダム**。一般客も同じパレットのどれかなので色では見分けられない）。好きな商品棚の近くで**「盗む」ボタン**を押し続け、5秒とどまると盗み成功（離すと中断。その間は目立つ）。盗んだ商品を出口（緑ゲート）から持ち出すと**商品のポイントを獲得**。**店の外に出たらそのターンには戻れない**（チキンレース方式）。仲間の頭上には名前が出る（監視カメラには映らない）
- **監視サイド**: 2人とも監視カメラ役。店内のカメラを**ONLINE⇔OFFLINE でトグル**（同時 ONLINE は1人3台まで。画面上寄りに3枚のモニタ、一番下にカメラマップ。モニタにカーソルを乗せると拡大）。映像の怪しいネズミをクリックすると「ダウト」
  - プレイヤーのネズミを当てたら、そのネズミは**所持中のポイントを没収され、退場**する（ターンは続く。まんびきサイド全員が退場したら即終了）
  - 一般客だったら空振り。ダウトは**1ターンにつき各プレイヤー3回まで**
- **監視の可視化**: ONLINE のカメラは**ポール上部の球体が赤く発光**し、**視野に入っている床が明るくなる**。まんびきサイドは「みられている場所」と死角を見分けながら動く。カメラマップには自分が ON にしたカメラの視野が**赤**、相方の視野が**青**で描かれる
- **勝敗**: ラウンドごとに合計ポイントの多いチームがそのラウンドを獲得。**獲得ラウンド数**の多いチームの勝ち。同数なら合計ポイント、それも同じなら引き分け（資料の「合計ポイント制」ではなく現状のセット制を維持している）
- **試合の流れ**（資料の「フロー」章）: タイトル（PRESS TO START）→ イントロダクション（2画面・SKIP可）→ 名前入力 → エリアの住所（一覧から参加 / 住所を入力 / 「新たな住所をゲットする！」で自動発番。ラウンド数とステージは「くわしい設定」）→ ロビー「トレトレバトル！」（TEAM PINK / BLUE のカプセルを選ぶ・ホストが先攻を選ぶ・START）→ **作戦会議タイム（30秒）**: 両チームとも棚ごとの商品とポイントが載った俯瞰マップを見る（まんびきサイドには今回の変装も表示）→ **フィールドインサート**（店内をなめる映像3秒）→ 攻守それぞれのスタート画面で 3・2・1 → 第1ターン → 作戦会議（30秒）→ インサート → 3・2・1 → 第2ターン → **ラウンド終了シークエンス**（PINK vs BLUE の得点表。勝敗表記なし）→ 次のラウンド … → **最終結果**（得点表）→ **セレモニー**（WINNER "PINK TEAM" !!）→ **ネクスト選択**（もう一度勝負する / 別のエリアで勝負する / ゲームを止める）→ 「止める」は**ゲーム中止警告**（いまいるエリアから抜けます。よろしいですか？）
- **ステージ**: エリア作成時にホストが選ぶ。選択は部屋の全員に共有され、開始時に確定する
  - **スタンダード**: 従来の広い売り場・カメラ12台
  - **シンプル**: 小さな売り場・カメラ6台・NPC少なめ
  - **自作ステージ**: タイトル画面の「🛠 ステージエディタ」で作ったステージ。「くわしい設定」のステージ選択に 🛠 付きで出る（下記「ステージエディタ」）
  - **2フロア**: 奥半分が2階建て。東側のスロープで2Fへ上がれる（NPCも行き来する）。出口は1Fのみ。カメラは1Fに8台・2Fに4台。カメラマップ／ミニマップは1F・2Fが横に並び、退場後の観戦（俯瞰）はFキーで表示フロアを切り替える

| 役割 | 操作 |
| --- | --- |
| 🐭 まんびきサイド | WASD / 矢印キーで移動、画面下部の「盗む」ボタンで盗み開始。左下のミニマップ（監視サイドと同じ図）に自分の位置が出る |
| 📹 監視サイド | 画面下のカメラマップの番号クリック or 数字キーでカメラの ON/OFF 切替（3台まで）、中央の映像内のキャラをクリックでダウト、Mでカメラマップの表示切替 |

### コントローラー（PS4 DualShock 4）

キーボード・マウスと併用できる。ブラウザが `standard` マッピングとして認識するゲームパッドが対象（接続後、何かボタンを押すと認識される）。

| 場面 | 操作 |
| --- | --- |
| 🐭 まんびきサイド | 左スティックで移動（倒し具合で速さが変わる）。一人称では左スティック上下で前進・後退、右スティック左右（と左スティック左右）で向きを変える。**×を押している間**だけ盗む（離すと中断）。△で視点切替（退場後の観戦では俯瞰のフロア切替） |
| 📹 監視サイド | 左スティックで照準カーソルを動かす（照準を乗せたモニタが拡大）。×で照準の位置をクリック（カメラマップの番号なら ON/OFF、映像内のキャラならダウト）。□でカメラマップの表示切替。マウスを動かすと照準は消え、スティックか×で戻る |
| メニュー | 十字キー or 左スティックで選択枠を移動、×で決定、○で戻る、右スティック上下でスクロール。名前と住所の入力はキーボード。ステージエディタは非対応 |

- 盗む棚の指定（お題）はない。まんびきサイドはいつでも好きな棚を狙える。「盗む」ボタンはまんびきサイドにしか表示されない
- ゲームバランスは `src/config.ts` の数値で調整できる（ダウト回数・作戦会議の秒数・インサートの秒数など）。資料で未決の「逆転要素（ラウンドごとの秒数増 or ポイント増）」は未実装

## ステージエディタ

タイトル画面の「🛠 ステージエディタ」から開く。マス目（1マス = 1m）の上をドラッグ・クリックして店を作る。

- **広さ**: 横×縦のマス数（壁の内側。12×10〜60×40）。左上（奥の壁の左端）を基準に伸び縮みする
- **棚**: 「棚を描く」で空きマスをドラッグ。右パネルで**料金帯**（金 500pt〜／銀 300〜499pt／銅 200〜299pt／水色 〜199pt／おまかせ）と**高さ**（高い棚＝カメラの視線を遮る／平台＝遮らない）を選ぶ。料金帯を決めた棚にはその帯の商品がラウンドごとにランダムで入る。棚をクリックすると選択でき、ドラッグで移動、四隅の□で大きさ変更、ラベル（マップに表示）を付けられる。盗みスポット（黄色の点）は、前が通路になっている面に自動で付く
- **カメラ**: 「カメラを置く」で、置きたい場所から映したい場所（注視点＝映像の中心）までドラッグ。視野（棚・壁で遮られた実効範囲）が赤く表示され、塗られていない床が死角
- **出口・スポーン地点**: 「選択・移動」でドラッグ（出口は奥の壁の上を左右に。幅はステージ設定）
- **ダミーNPCの人数**: ステージ設定で指定。NPCは幅2マス以上の通路しか歩けない（「NPCが歩ける場所」にチェックで確認できる）
- **チェック**: スポーンが棚の上・出口まで行けない等の ⛔ があると遊べない。⚠️（カメラ無し・NPCが通らない幅1マスの通路 等）は遊べる
- **テストプレイ**: 「▶ まんびきサイドで歩く」「▶ 監視サイドで見る」で、その場で1人用のターン（NPCあり）を回して確認できる。右下のパネルで役割の切替・エディタへ戻る
- **保存と共有**: 編集内容はブラウザ（localStorage）に自動保存。別のPCへは「JSON書き出し」→「JSON読み込み」で渡す。対戦では、エリアを作る人が「くわしい設定」のステージ選択で自作ステージを選べば、データがエリアに書かれて全員に配られる（他の3人は何も持っていなくてよい。Firebase のルール変更も不要）
- Ctrl/⌘+Z で元に戻す、Shift 付きでやり直す、Delete で選択中の棚・カメラを削除
- 2フロア（スロープ）はエディタ非対応（組み込みの「2フロア」のみ）

## セットアップ

```bash
npm install
npm run dev
```

### ローカルモード（Firebase不要・すぐ試せる）

`.env` が無い場合は自動でローカルモードになり、**同一PCのブラウザタブ間**で同期する。
`npm run dev` して同じURLをタブで4つ開き、同じ住所のエリアに入れば1人で動作確認できる。

### オンラインモード（Firebase）

1. [Firebaseコンソール](https://console.firebase.google.com/)でプロジェクト作成
2. Realtime Database を作成（テストモードでOK。ロケーションは asia-southeast1 など）
3. プロジェクトの設定 > マイアプリ > ウェブアプリを追加して設定値を取得
4. `.env.example` を `.env` にコピーして値を記入
5. `npm run dev` → 各プレイヤーが同じ住所のエリアに参加

プロトタイプ用のDBルール（全公開なので遊び終わったら閉じること）:

```json
{
  "rules": {
    "rooms": { ".read": true, ".write": true }
  }
}
```

## 実装メモ

- **NPCの同期**: NPCはゲームseedから決定論的に動く（`NpcSim.posAt(t)`）。全クライアントが同じ計算をするため位置の通信が不要。seedはターンごとに変わり、**作戦会議タイムの開始時に発行**する（作戦会議のマップに商品とポイントを出すため。`buildWorld` を使い捨てのシーンで呼んで `mapData` だけ使う）
- **部屋の後始末**: プレイヤー情報は切断時に自動削除されるが、`phase`・`events` はホストの「もう一度 勝負する」でしか消えない。そのため、入室時に自分以外の誰もいない部屋は残骸とみなして `phase` をロビーに戻し、`events`/`pos`/`cams` を削除する。保険として、startAt が1ターン分より十分古い `playing` はロビー扱いにする（`isStalePhase`）
- **スコア**: `escape` イベント（持ち出した商品の合計ポイント `value` を含む）の積み上げから全クライアントが同じ集計をする。イベントは試合を通して保持し、ロビーに戻るときに消す
- **ターン進行**: 時間切れ、またはまんびきサイド全員が退場した時点（ダウト演出後）。ホスト（不在時は2秒後に誰でも）が `phase` を書き込む楽観的な方式（プロトタイプ想定）
- **フェーズ**: `lobby` → `planning`（作戦会議。`until` まで。ホストの START と第1ターン終了時に入る。`seed` と `firstMice` を持つ）→ `playing`（`startAt`。毎ターン startAt の前に `introSec`＋`countdownSec` の猶予）→ `setEnd`（次のラウンドがあるとき。`until` まで表示）→ `planning`（次のラウンド）… → `ended`。`planning`/`setEnd` の終了は main.ts の setInterval がホスト（不在時は2秒後に誰でも）として次のフェーズを書く。試合構成（`set`/`sets`/`stages`/`results`/`firstMice`）は phase に持ち回る
- **先攻**: ロビーの選択は `rooms/{room}/first`（`'A'`/`'B'`/`'random'`）。START 時に `phase.firstMice` へ確定し、`miceTeamOf(round, firstMice)` でそのターンのまんびきサイドを決める
- **試合終了後**: `ended` で Game が最終結果 → セレモニー → ネクスト選択を出す。選択は各自ローカル（`Game.onEndChoice`）で、「もう一度」はエリアのロビーへ（ホストなら phase を `lobby` に戻す）、「別のエリア」は退室してエリア一覧へ、「止める」は確認後に退室してタイトルへ。ホストが phase を戻しても、まだセレモニー等を見ている人の画面は消さない（`Game.inEndSequence`）
- **セットごとの集計**: イベントに `set` を含め、Game は自分のセットのイベントだけを集計する（イベントは試合を通して残す）。試合構成は `rooms/{room}/match`（`{ sets, stages }`）にエリア作成時に書く
- **アクティブなエリア一覧**: `roomIndex/r_{code}/{pid}` = 名前 を入室時に書き、切断時（と退室時）に削除。メンバーが1人以上いるエリアだけ一覧に出す（`rooms` 全体を購読すると位置情報まで流れるため別ノードにしている）
- **名前ラベルの秘匿**: 名前スプライトは Three.js のレイヤ2に置き、まんびきサイドのクライアントの追従/一人称カメラだけがそのレイヤを描画する。CCTVカメラ・観戦の俯瞰では描画しない
- **Firebase の注意**: `set()` に `undefined` を含むオブジェクトを渡すと書き込みが拒否される。省略可能なフィールドは入れないこと
- **ダウト成功**: `caught` イベントを受けた当人が演出時間だけその場で固まった後、姿を消して退場し、俯瞰で観戦になる（所持商品は没収）。ダウトは成功でも回数を消費する
- **脱出（チキンレース）**: 商品を持って出口ゾーンに入ると `escape` イベントで所持ポイント分をスコアに加算し、当人はダウト時と同じ退場処理（観戦）になる。リスポーンはしない。まんびきサイド全員が退場（ダウト or 脱出）したらターン即終了
- **ダウト判定**: CCTVのクリック位置から該当カメラのNDC座標を求めてレイキャスト。プレイヤーに当たれば `caught`、NPCなら `miss`
- **監視状態の同期**: 各監視サイドのオンラインカメラIDを `rooms/{room}/cams/{pid}` に書き、全クライアントが購読して球の発光と床ハイライトに反映する
- **視野と死角**: カメラの実効視野はマップ表示・床ハイライト・死角リスポーン探索で同じ2Dレイキャスト（`castRay`）を使って一貫させている。死角リスポーンは1Fの全カメラから見えない歩行可能地点を起動時に自動探索する
- **ステージ選択**: エリア作成時の構成を `rooms/{room}/match` に書き、ロビーの全員が購読して表示する。開始時に `phase.stage` へコピーし、以降の `phase` にも引き継ぐ
- **自作ステージ**: エディタのデータ（`CustomStageData`。マス座標）は `toStageDef` で組み込みと同じ `StageDef` に変換してからゲームに渡す。マス目の外周が壁の内面に一致するよう `rect` は壁の厚みの半分だけ外に広げ、マスの角がNPCの歩行グリッド（整数座標）に乗るよう原点を整数にしている。棚には料金帯（`ShelfDef.tier`）と盗みスポットの位置（`ShelfDef.spots`）を直接持たせる（組み込みステージは従来どおり全商品ランダム・`sides` からの自動配置）。エリア作成時に使う自作ステージを `rooms/{room}/match.custom`（ID → データ）に書き、各クライアントは `match` を受信したときに `registerStage` で登録して `getStage(id)` で引く。`match` が届く前にゲームを作ると別のステージになるので、ロビーは `match` の受信まで `onUpdate` を呼ばない。Firebase は空配列を消し配列をオブジェクトで返すことがあるため、受け取ったデータは必ず `normalizeStageData` を通す（名前・ラベルからHTMLになる文字も落とす）
- **複数フロア**: 各フロアは独立した2Dレイアウト（`FloorDef`）で、スロープ（`RampDef`）の矩形内では両端のフロアの高さを線形補間する。プレイヤーはスロープの端（下のフロアからは下端、上のフロアからは上端）からしか出入りできず、横は手すりで塞ぐ。歩行グリッド（`NavGrid`）はフロアごとのレイヤをスロープ上端のリンクで繋いでおり、NPCも坂を通って行き来する。上階の静的メッシュは Three.js のレイヤ1に置き、1Fにいるまんびきサイドの追従カメラでは非表示にして床板で視界が塞がれないようにしている（CCTV・一人称は全レイヤ描画）。位置同期には `f`（フロア番号）を含める。2Dの視野（マップ・床ハイライト）はフロアの範囲内で打ち切り、吹き抜け越しの見下ろしは扱わない
